# SDLC Docs (절차)

양식 만들기·자동 항목(규모·스택·모듈·API·테이블·패턴·보안 점검)·완성도 판정·게이트는 **LLM 없이** `axnavi doc`·`axnavi adr`·`axnavi gate` 가 한다.  
이 절차는 그 위에서 **서술 절만** 근거를 붙여 채운다.

**지어내지 않는다:** 일정·담당자·성명·수치·업무 규칙은 사용자 입력·명세 리포트·코드에서 확인된 것만 쓴다. 모르면 `확인 필요` 로 남긴다.  
**승인하지 않는다:** 문서 머리말의 `상태:` 는 `작성중` 으로 둔다. `승인` 은 사람이 바꾼다(게이트의 승인 항목은 사람의 검토를 뜻한다).  
**덮어쓰지 않는다:** 이미 있는 산출물은 사람이 쓴 절을 지우지 않는다. 빈 절·양식 그대로인 절만 채운다.

```
CLI = node "${CLAUDE_PLUGIN_ROOT}/packages/cli/src/bin.mjs"
```

## Phase 0: 대상 확인

| 요청 | 종류 | 단계 |
|------|------|------|
| 프로젝트 정의서 | `project` | 요구(req) |
| 요구사항 명세서·SRS | `srs` | 요구(req) |
| 설계서·SDD | `sdd` | 설계(design) |
| 개발 표준 | `standards` | 설계(design) |
| 진행 기록서 | `progress` | 개발(dev) |
| 품질 검증서 | `quality` | 테스트(test) |
| ADR·아키텍처 결정 | ADR | 설계(design) |
| 게이트만 | — | 요청한 단계 |

먼저 현황을 본다.

```bash
$CLI doc list --root "[프로젝트 루트]"
```

## Phase 1: 양식 만들기

없는 산출물만 만든다. 조직 양식이 `.axnavi/templates/<종류>.md` 또는 `AXNAVI_TEMPLATES_DIR` 에 있으면 그것을 쓴다(출력에 양식 출처가 찍힌다).

```bash
$CLI doc new [종류...] --root "[프로젝트 루트]"
```

자동 항목이 `(인덱스 없음 …)` 으로 나오면 `axnavi index build` 를 먼저 권한다. 보안 점검 항목이 비었으면 `$CLI scan security --root "[프로젝트 루트]" --format json --out "[프로젝트 루트]/_workspace/reports/security_scan.json"` 후 `--force` 없이 해당 절만 손으로 옮긴다.

---

## Phase 2: 서술 절 채우기

산출물 파일을 `Read` 로 열고, 머리말의 작성 필수 절(`<!-- 작성: … -->` 표시가 있는 절)을 순서대로 채운다. 채운 절에서는 `<!-- 작성 … -->` 주석을 지운다.

근거 출처(이 순서로 찾는다).

| 근거 | 쓰는 곳 |
|------|---------|
| `_workspace/00_spec_report.md` (spec-gate) | 목적·범위·제약·우선순위·인수 기준 |
| 사용자가 이번 대화에서 준 내용 | 이해관계자·일정·결정 |
| 인덱스 질의(`query-index.mjs`) | 변경 설계 대상·데이터 설계·인터페이스 |
| `.claude/patterns/*.md` | 개발 표준의 적용 패턴·코딩 규칙 |
| `_workspace/reports/*.json` (review·scan) | 품질 검증서 결함 현황 |

인덱스는 원본 JSON 을 열지 말고 질의한다.

```bash
node "${CLAUDE_PLUGIN_ROOT}/agents/lib/query-index.mjs" endpoint --root "[프로젝트 루트]" --path "[경로 일부]"
node "${CLAUDE_PLUGIN_ROOT}/agents/lib/query-index.mjs" table --root "[프로젝트 루트]" --table "[테이블]"
```

근거가 없는 절은 `확인 필요: [누구에게 무엇을]` 한 줄로 남긴다. 게이트는 `확인 필요` 줄만 있는 절을 **미작성**으로 본다 — 질문이 풀려야 통과한다. 남긴 목록은 Phase 4 보고에 옮긴다.

---

## Phase 3: ADR

설계 중 되돌리기 어려운 결정(구조·데이터 모델·연계 방식·라이브러리·현행 패턴과 다르게 가는 것)이 나오면 ADR 로 남긴다.

```bash
$CLI adr new "[결정 제목]" --root "[프로젝트 루트]"            # 상태 기본 '제안'
$CLI adr new "[결정 제목]" --status 채택 --root "[프로젝트 루트]"  # 사용자가 결정했다고 말한 경우만
```

만든 파일을 열어 맥락·결정·대안·결과를 채우고, 설계서의 "아키텍처 결정" 절에 `ADR-NNNN 제목` 을 적는다.

## Phase 4: 게이트와 보고

```bash
$CLI gate [단계] --root "[프로젝트 루트]" --record
```

`--record` 는 진행 기록서의 "단계 게이트 이력" 표에 한 줄을 덧붙인다. 개발(dev) 이상 단계는 `axnavi review` 를 함께 돌린다 — 변경 범위가 있으면 `--diff A..B` 를 넘긴다.

사용자에게 보고한다.

```
산출물: [만든·채운 파일]
게이트 [단계]: [GO | HOLD | STOP]
  ⛔ 필수 미충족: [항목 — 내용]
  ⚠️ 권고 미충족: [항목 — 내용]
확인 필요: [Phase 2 에서 남긴 항목]
다음: [승인 요청 대상 문서 / 다음 단계 게이트]
```

## 에러 핸들링

| 상황 | 대응 |
|------|------|
| `산출물 양식을 찾지 못했습니다` | 조직 양식 폴더 경로(`AXNAVI_TEMPLATES_DIR`)와 파일 이름(`<종류>.md`)을 확인하도록 안내 |
| 게이트 dev 의 "리뷰를 돌리지 못함" | git 저장소가 아니거나 범위가 잘못됨 — `--diff` 를 바로잡거나 `--skip-review` 로 문서만 본다 |
| 사용자가 승인까지 해 달라고 함 | 상태를 바꾸지 않고, 승인은 검토자가 머리말에서 바꾼다고 안내 |
