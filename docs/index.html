정직한 보고

"없다"는 것도
답의 절반입니다.

  • 찾은 것 · 확인했는데 없는 것 · 확인하지 못한 것

    셋을 나눠 보고합니다. "관련 컬럼 없음 · SQL 0건" 같은 사실이 판단에 바로 쓰입니다.

  • 백엔드와 프론트엔드를 함께

    두 저장소를 담은 상위 폴더에서 띄우면, 저장소마다 에이전트를 하나씩 띄워 병렬로 훑습니다.

  • 썼다고 말한 리포트는 정말 썼는지 확인

    답이 리포트 파일을 안내했는데 이번 실행에서 쓰이지 않았으면 끝에 알려 줍니다. 앞선 실행의 옛 파일을 새 결과로 착각하지 않게 합니다.

안전장치

고치기 전에, 무엇이
바뀌는지부터 보여 줍니다.

  • 바뀌는 줄을 파일의 실제 줄 번호로

    파일 수정은 앞뒤 문맥과 함께, 명령 실행은 명령 전체를 보여 주고 묻습니다. 허용·거부 이력은 감사 기록으로 남습니다.

  • 영향도 → 변경 → 검증

    /modify 는 쓰는 곳을 먼저 확인하고, 컨벤션에 맞춰 고친 뒤, 검증 명령을 실제로 돌려 GO · HOLD · STOP 을 냅니다. 돌리지 못한 검증은 통과로 치지 않습니다.

  • 노력은 위험만큼

    라벨 한 줄 같은 작은 변경은 가볍게 직접 확인하고, 스키마 · 트랜잭션 · 인증 · 공통 모듈에 닿으면 독립 에이전트가 따로 검증합니다.

  • 사람이 정할 일은 묻습니다

    프로젝트 구성처럼 사람이 결정할 것만 선택지로 띄웁니다. 선택지 개수에 제한이 없고, 건너뛴 질문은 확정으로 기록하지 않습니다.

작업 흐름

지도를 한 번 그리면,
그다음은 말로 부탁하면 됩니다.

명령을 외우지 않아도 됩니다. "하네스 초기화 해줘", "이거 고치면 어디 영향 가?" 처럼 말하면 알맞은 스킬이 실행됩니다.

  1. axnavi index build

    지도 그리기

    소스를 전수 파싱해 인덱스 10종을 만듭니다.

    AI 호출 없음
  2. /harness-init

    프로젝트 익히기

    구조 · 컨벤션 · 도메인을 분석해 CLAUDE.md 와 패턴 프로필을 만듭니다.

    분석 · 작성 · 검증 에이전트
  3. /find · /flow

    찾고 따라가기

    기능 위치와 진입점부터 DB 까지의 처리 흐름을 봅니다.

    인덱스 질의 우선
  4. /impact

    영향 보기

    바꾸려는 대상을 쓰는 곳과 위험도를 먼저 확인합니다.

    호출 그래프 · SQL 사용처
  5. /modify

    안전하게 고치기

    허락을 받아 고치고, 검증까지 마친 뒤 결과를 보고합니다.

    GO · HOLD · STOP
스킬

유지보수의 거의 모든 일에,
맞는 스킬이 있습니다.

찾고 고치는 일뿐 아니라 새 화면을 만들고, 스택을 옮기고, SQL 을 점검하는 일까지. 모두 같은 지도와 같은 컨벤션 위에서 돕니다.

찾고 이해하기

/find
기능·키워드로 파일 · 클래스 · SQL 위치를 찾습니다.
/flow
기능 · API · 화면의 처리 흐름을 진입점부터 DB 까지 따라갑니다.
/agent legacy-decoder
주석 없는 레거시 코드의 의도와 동작을 사람이 읽는 말로 풀어 줍니다.
/wiki
분석 결과를 인수인계용 wiki 로 만듭니다. 호출 그래프도 그림으로 남습니다.

고치기

/impact
파일 · 함수 · SQL · 컬럼 · API 를 바꾸면 어디에 닿는지와 위험도를 봅니다.
/modify
영향도 확인 → 변경 → 패턴 · 실행 · 안전성 검증 순으로 고칩니다.
/vibe
게이트는 건너뛰되 프로젝트 패턴과 최소 검증은 지키는 빠른 작업입니다.

새로 만들기

/scaffold
이 프로젝트의 컨벤션 그대로 새 기능을 만듭니다. Controller · Service · DAO · DTO · 테스트까지.
/cross-repo-scaffold
백엔드와 프론트엔드(웹 · 모바일 · 관리자까지) 전체 스택 기능을 한 번에 만듭니다.

옮기기

/plan-migration
스택 마이그레이션 계획을 세웁니다. 인벤토리 · 매핑 표 · 단계별 계획 · 위험 등록 · 테스트 전략 · 롤백 · 체크포인트.

예: Struts 1 → Spring MVC, iBatis → MyBatis

SQL

/sql
SQL 문 · SQL ID · DDL · 변경분을 받아 사용처 · 인덱스 활용 · N+1 · 인젝션 · 트랜잭션 · 락 · 대량 처리 · 스키마 영향을 리뷰합니다.

확정 발견 · 조건부 권고 · 수정안 SQL 로 나눠 보고합니다.

백엔드와 프론트엔드를 함께

/pair-init
따로 있는 백엔드 · 프론트엔드 저장소를 연결하고, API 가 어긋난 곳을 찾습니다.
/cross-repo-modify
한쪽에서 시킨 수정을 관련된 저장소에 함께 반영합니다.
/agent api-bridge
API 계약을 뽑아 검증하고, 프론트엔드 서비스 스텁을 만듭니다.

준비와 관리 — /harness-init 하네스 초기화 · /spec-gate 착수 전 요구 명확화 · /publish-wiki wiki 를 중앙 DB 에 발행 · /harness-clean 하네스 제거. 명령을 외우지 않아도 말로 부탁하면 알맞은 스킬이 실행됩니다.

설치

Node.js 와 Claude 구독이면 충분합니다.

필수 런타임 의존성은 0 입니다. 이미 쓰는 claude 로그인을 그대로 쓰므로 API 키도, 추가 비용도 필요 없습니다.

설치
npm i -g --allow-remote=all https://codeload.github.com/Malburi/AX-NAVI-CLI/tar.gz/refs/tags/v0.1.0-alpha.33
확인 · 시작
cd 내-프로젝트
axnavi doctor
axnavi index build
axnavi

새 판은 대화형 모드가 하루 한 번 알려 줍니다. axnavi upgrade 한 줄로 올립니다.

npm 이 외부 주소에 붙지 못하는 PC 는 파일로 받아 설치합니다. 의존성은 사내 npm 저장소에서 받습니다.

GitHub 에는 닿는데 npm 이 막힐 때 (PowerShell)
Invoke-WebRequest "https://codeload.github.com/Malburi/AX-NAVI-CLI/tar.gz/refs/tags/v0.1.0-alpha.33" -OutFile "$env:TEMP\axnavi.tgz" -UseBasicParsing
npm i -g "$env:TEMP\axnavi.tgz"
GitHub 에도 닿지 않을 때 — 배포 담당자에게 받은 파일
npm i -g C:\경로\axnavi-0.1.0-alpha.33.tgz --omit=optional

PowerShell 에서 running scripts is disabled 가 나오면 axnavi.cmd 로 부르세요.
