# Tier와 토큰 비용

`harness-init`은 분석 깊이를 Standard와 Full 두 Tier로 나누고, LLM 구간에 들어가기 전에 예상 토큰을 보여 줍니다. 이 페이지는 두 Tier가 무엇이 다른지, 견적이 어떤 공식으로 계산되는지, 견적에 포함되지 않는 항목은 무엇인지, 그리고 초기화 비용을 이후 작업에서 언제 회수하는지를 정리합니다. 초기화 전에 비용 규모를 미리 가늠하고 싶을 때 읽으세요.

## Tier 두 가지

기본 Tier는 **Full**입니다. 레거시 유지보수에서는 얕은 분석이 놓치는 위험(미해결 관계·인증 우회·트랜잭션 경계)이 재작업 비용보다 크다는 전제입니다. 인덱스가 없는 하네스는 후속 스킬이 동작하지 않으므로 인덱스를 생략하는 Tier는 없습니다.

| 항목 | Standard | Full (기본값) |
|------|----------|---------------|
| 선택 방법 | "빠르게 하네스 구축해줘"처럼 "빠르게"·"간단히"·"quick" 키워드, 또는 견적 화면에서 `2` 선택 | 키워드 없이 요청, 또는 "심층"·"깊게"·"마이그레이션"·"레거시"·"deep" 키워드 |
| analyzer 분석 범위 | Phase A + 스택에 해당하는 Phase B만 | Phase A + Phase B 전체 |
| 포함 내용 | 스택·구조, 의존성 그래프, 트랜잭션·외부 통신, 패턴 추출 | Standard 항목 + 데드코드, 환경 분기·인증 경로 |
| 데드코드 식별 | 미지원 | 지원 |
| writer·pattern-extractor·validator·harness-evaluator | 모두 실행 | 모두 실행 |
| 경계 QA · wiki | 온디맨드 (Phase 3.6 메뉴에서 선택 시만) | 온디맨드 (동일) |
| 모델 | 모든 에이전트 `claude-sonnet-5` | 모든 에이전트 `claude-sonnet-5` |
| 소요 시간 감각 | 3~5분 | 10분 내외 |
| 적합한 프로젝트 | 일반 웹 서비스, 소규모 모듈, 일상 유지보수 | 대형 레거시, 마이그레이션 대상, 대규모 수정 계획 |

두 Tier는 analyzer의 분석 범위만 다릅니다. 품질 게이트(validator·harness-evaluator·Phase 4 재생성)는 Standard에서도 그대로 유지되며, Opus로의 자동 승격은 어느 Tier에서도 일어나지 않습니다.

## Tier가 정해지는 순서

1. 요청문에 키워드가 있으면 Phase 0에서 즉시 확정하고 이후 질문을 건너뜁니다.
2. 키워드가 없으면 기본 Full로 두되, 인덱싱(2-0.5)이 끝나 규모가 확정된 뒤 2-0.7에서 실제 견적과 함께 한 번만 확인합니다.
3. 결정된 값은 `_workspace/00_init_scope.md`의 `tier:` 행에 기록되고, 부분 재실행·인덱스 리프레시는 이 값을 재사용해 다시 묻지 않습니다.

```text
이제 LLM 분석 구간입니다. 예상 규모:
  Tier Full 기준 · 약 27분 · 약 319,000 토큰
  판정이 필요한 미해결 관계: 200건

  1. Full 로 진행      — 심층 분석 (마이그레이션·대규모 수정 계획이 있으면 권장)
  2. Standard 로 진행  — 위 견적의 약 60% (일상 유지보수에는 대개 충분)
  3. 여기서 중단        — 인덱스만 두고 나중에 이어서 (인덱스는 그대로 남습니다)
```

## 견적 공식

견적은 `agents/lib/ai-budget.mjs`의 `estimateCost`가 인덱스 메타데이터(`_meta.json`·`_analysis_input.json`)만 읽어 계산합니다. 정확한 예측이 목적이 아니라 시작 전에 자릿수를 보여 주는 것이 목적이며, 계수는 2026-08 실측 세션(파일 2천~5천 규모 레거시)에서 역산한 값입니다.

```text
estimated_tokens = 고정비 + 파일수 × 파일당 + min(판정그룹, 2000) × 900 + 25,000
estimated_minutes = max(3, estimated_tokens / 12,000)
```

| 항목 | Full | Standard | 의미 |
|------|------|----------|------|
| 고정비 | 70,000 | 45,000 | 에이전트 지침 + 산출물 왕복 |
| 파일당 | 22 | 12 | 대표 파일 열람과 리포트 작성이 파일 수에 비례 |
| 판정그룹당 | 900 | 900 | 미해결 관계 한 그룹을 판정할 때 소스 구간을 열어 확인하는 비용. 가장 변동이 큰 항목 |
| 판정그룹 상한 | 2,000 | 2,000 | 이 값을 넘는 그룹은 견적에 더하지 않음 |
| 패턴 추출 | 25,000 | 25,000 | 레이어별 표본에 걸려 상한이 뚜렷함 |

"판정그룹"은 미해결 관계의 발생 위치 수가 아니라 같은 패턴을 묶은 고유 그룹 수(`unresolved_decidable_group_count`)입니다. 레거시 코드베이스는 같은 애매함이 수백 곳에서 반복되므로 발생 위치로 계산하면 크게 과대추정됩니다. 옛 인덱스에 그룹 필드가 없으면 발생 위치 수로 폴백합니다.

## 규모별 예시

아래는 공식을 그대로 대입한 값입니다. 실제 값은 판정그룹 수에 따라 크게 달라지므로 자릿수 참고용으로만 보세요.

| 규모 | 파일 수 | 판정그룹 | Full 견적 | Standard 견적 | Full 예상 시간 |
|------|---------|----------|-----------|---------------|----------------|
| 소형 | 500 | 50 | 151,000 (≈150K) | 121,000 | 약 13분 |
| 중형 | 2,000 | 200 | 319,000 (≈320K) | 274,000 | 약 27분 |
| 대형 | 5,000 | 500 | 655,000 (≈650K) | 580,000 | 약 55분 |

예상 시간은 실측 기준 분당 약 12K 토큰(모델·재시도 포함)으로 환산한 값이라 README의 "Full 10분 내외"보다 보수적입니다. 판정그룹이 적은 프로젝트는 훨씬 빨리 끝납니다.

## 견적에 포함되지 않는 항목

`estimateCost`는 analyzer·writer·pattern-extractor 구간만 계산합니다. 다음 항목은 별도로 더해 생각하세요.

| 항목 | 추가 토큰 | 비고 |
|------|-----------|------|
| validator + harness-evaluator | 약 20K~35K | 두 Tier 모두 항상 실행. Standard 하한, Full 상한 |
| Phase 4 타겟 재생성 | +40K~80K (Standard) / +60K~150K (Full) | Eval 80점 미만 또는 인덱스 무결성 게이트가 걸렸을 때만, 최대 1회 |
| 경계 QA | +10K~20K (Standard) / +20K~40K (Full) | Phase 3.6 메뉴에서 선택 시만 |
| wiki 생성 | 0 | `wiki_generator.py`가 인덱스를 그대로 렌더링 |
| wiki AI 해설 옵션 | +5K~10K | `overview.md` 한 페이지만 LLM 작성 |
| 인덱싱 (2-0.5) | 0 | `build-index.mjs`는 LLM을 쓰지 않음 |
| 하네스 파일 조립 · 기계 검증 | 0 | `skills_builder.py`·`validator_checks.py`·`validate-harness.mjs` |

## 인덱싱만 먼저 돌려 실제 견적 보기

초기화를 시작하지 않고 내 프로젝트의 견적만 보고 싶다면 두 가지 방법이 있습니다.

첫째, 대화에서 "하네스 초기화해줘"를 입력하고 2-0.7 견적 화면에서 `3`(여기서 중단)을 고르는 방법입니다. 인덱스는 남고 LLM은 한 번도 호출되지 않습니다.

둘째, 터미널에서 인덱서와 견적 스크립트를 직접 실행하는 방법입니다. 스크립트는 대상 프로젝트가 아니라 플러그인 설치 루트에 있으므로 `$env:CLAUDE_PLUGIN_ROOT`(PowerShell) 또는 `$CLAUDE_PLUGIN_ROOT`(bash)로 참조합니다. 이 변수가 비어 있으면 플러그인 캐시 디렉터리(예: `~/.claude/plugins/cache/ax-navi/...`)의 절대경로를 직접 넣으세요.

```powershell
node "$env:CLAUDE_PLUGIN_ROOT/agents/lib/build-index.mjs" --root "D:\work\order-service" --mode init --tier Full
node "$env:CLAUDE_PLUGIN_ROOT/agents/lib/ai-budget.mjs" estimate --root "D:\work\order-service"
```

`estimate`는 `files`·`tier`·`decidable_unresolved`·`symbols`·`estimated_tokens`·`estimated_minutes`를 JSON으로 출력합니다. `_workspace/index/_meta.json`이 없으면 "estimate에는 인덱스가 먼저 필요합니다"로 종료하므로 반드시 인덱싱을 먼저 돌려야 합니다.

## 예산 게이트가 하는 일

인덱싱 직후 `ai-budget.mjs init`이 `_workspace/ai-budget.json`을 만들고 시간·토큰 한도를 견적의 2배로 걸어 둡니다. 목적은 계획대로 진행되는 프로젝트를 막는 것이 아니라 견적을 몇 배씩 벗어나는 이상 상황만 잡는 것입니다.

- analyzer·writer·pattern-extractor 호출 전에 `claim`으로 역할당 initial 1회를 확인합니다. 거부되면 그 호출을 하지 않고 중단합니다. 하드 스톱이 의도입니다.
- 각 역할이 끝나면 견적의 60%(analyzer)·25%(writer)·15%(pattern-extractor)를 `record`로 기록합니다. 실사용 토큰 카운터가 없어 사전 배분 장부로 근사한 값입니다.
- Phase 4 재실행은 `--kind retry`로 별도 한도를 씁니다.
- 최종 보고의 `AI 예산 증적` 줄에서 세션 ID와 initial·retries 사용량을 확인할 수 있습니다.

Node가 없는 환경에서는 예산 게이트가 적용되지 않고 그 사실이 보고에 남습니다.

## 실측표 (재측정 예정)

`docs/harness-description.md`의 아래 수치는 analyzer가 Opus로 실행되던 이전 설정에서 측정한 값입니다. 현재는 모든 에이전트가 `claude-sonnet-5`로 고정돼 있어 재측정 예정이며, 상대적 비율을 보는 용도로만 참고하세요.

| 항목 | Standard (중규모) | Full (대규모) |
|------|-------------------|---------------|
| analyzer | ~40K–80K | ~100K–200K |
| writer | ~25K–45K | ~40K–80K |
| pattern-extractor | ~10K–20K | ~20K–35K |
| validator | ~8K–15K | ~12K–20K |
| harness-evaluator | ~8K | ~10K–15K |
| 초기화 합계 | ~99K–176K | ~230K–438K |
| Phase 4 재생성 (해당 시) | +40K–80K | +60K–150K |

## 초기화 이후 작업별 절감

초기화 이후에는 각 스킬이 `_workspace/index/*.json`을 질의하므로 코드를 다시 탐색하지 않습니다. 같은 문서의 작업별 비교표입니다.

| 작업 유형 | 하네스 미사용 | 하네스 사용 (Standard) | 하네스 사용 (Full) |
|-----------|---------------|------------------------|--------------------|
| 기능 위치 탐색 | ~8K–25K | ~2K–4K | ~2K–3K |
| 영향도 분석 | ~15K–50K | ~5K–10K | ~3K–6K |
| 신규 기능 개발 | ~20K–80K | ~6K–12K | ~4K–8K |
| SQL 리뷰 | ~10K–40K | ~5K–8K | ~3K–5K |
| 안전 변경 | ~25K–100K | ~8K–15K | ~5K–10K |

## 손익분기점

| 규모 | 초기화 비용 | 작업당 절감 | 손익분기점 |
|------|-------------|-------------|------------|
| 중규모 (Standard) | ~137K | ~20K/작업 | 약 7회 |
| 대규모 (Full) | ~334K | ~45K/작업 | 약 8회 |

작업 종류가 다양할수록 인덱스 재사용률이 높아져 손익분기점이 앞당겨집니다. 일회성 소규모 작업이라면 하네스 없이 진행하는 것도 합리적이고, 두 달 이상 유지보수가 이어질 예정이면 Standard, 레거시 전환·대형 SI라면 Full이 권장됩니다. 대규모에서는 토큰 절감보다 경계면 불일치·데드코드·트랜잭션 위험을 구조적으로 잡아내는 가치가 더 큽니다.
