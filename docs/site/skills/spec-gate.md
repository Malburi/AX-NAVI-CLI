# spec-gate

작업 시작 전 소크라테스식 인터뷰로 목적·범위·제약을 명확화하는 스킬이다. harness 초기화, 마이그레이션, 대형 기능 개발처럼 복잡한 작업을 시작하기 전에 5개 영역(범위·목표·제약·레거시·우선순위)에서 표적 질문을 던져 모호성 점수를 0.2 이하로 낮춘다.

## 언제 쓰는가

| 구분 | 트리거 문구 |
|------|-------------|
| 한국어 | "명세 명확화", "요구사항 정리해줘", "작업 범위 정해줘", "어디서부터 시작해야 해", "뭐부터 해야 해", "범위 정의해줘", "작업 목표 정리해줘", "시작 전 정리" |
| 영어 | "spec gate", "ambiguity check", "scope clarify" |
| 슬래시 호출 | `/ax-navi:spec-gate` |
| 자동 트리거 | 없다. harness-init은 spec-gate를 자동 호출하지 않으므로, harness-init 실행 전 목적·범위를 먼저 정리하고 싶으면 이 스킬을 독립적으로 먼저 호출한다. |

별칭은 없다. 신규 투입 후 첫 작업 전, 마이그레이션 계획 수립 전, 대형 기능 개발 전이 대표적인 사용 시점이다.

## 실행 흐름

```text
[사용자 요청]
     ↓
경량 스캔 + 맥락 파악
     ↓
질문 생성 (3~5개) → 사용자에게 제시
     ↓
사용자 응답 수신
     ↓
모호성 점수 계산
     ├── ≤ 0.2: GO → 명세 리포트 저장 → 다음 작업 안내
     └── > 0.2: 재질문 (1회 한도) → GO → 명세 리포트 저장
```

| 단계 | 하는 일 | 호출 에이전트·스크립트 | 사용자 개입 |
|------|---------|------------------------|-------------|
| Step 0 | `pwd`로 현재 디렉토리를 확인하고 어떤 작업을 앞두고 있는지(harness-init / 마이그레이션 / 대형 기능 개발 / 기타) 간단히 확인한다. | 없음 | 앞둔 작업 종류를 답한다. |
| Step 1 | `question` 모드로 spec-clarifier를 호출한다. 루트 파일만 경량 스캔해 3~5개 질문을 만들고, 반환된 질문 세트를 그대로 사용자에게 제시한다. | [spec-clarifier](/agents/spec-clarifier.md) (`mode: question`) | 질문에 답한다. 모르면 "없음"·"모름", 전체를 건너뛰려면 "스킵"이라고 답한다. 응답 전에는 다음 단계로 진행하지 않는다. |
| Step 2 | `score` 모드로 spec-clarifier를 호출해 응답을 점수화하고 `_workspace/00_spec_report.md`를 작성한다. | [spec-clarifier](/agents/spec-clarifier.md) (`mode: score`) | 없음 |
| Step 3 | 리포트의 신호를 읽어 분기한다. | 리포트 읽기 | REFINE이면 재질문에 답한다. |
| Step 4 | 결과 요약을 표시하고 다음 단계를 안내한다. | 없음 | 없음 |

### Step 3 분기

| 신호 | 조건 | 동작 |
|------|------|------|
| **GO** | 점수 ≤ 0.2 | Step 4로 진행한다. |
| **REFINE** | 점수 0.21~0.4 | spec-clarifier가 작성한 재질문을 제시하고 응답을 받아 score 모드를 재실행한다(1회 한도). 그 뒤 Step 4로 진행한다. |
| **GO (미답변 진행)** | 점수 > 0.4 | 강제 중단 없이 Step 4로 진행한다. analyzer가 코드에서 직접 파악한다. |

2차 score 실행 후에는 점수와 무관하게 Step 4로 진행한다.

### 모호성 점수 계산 방식

spec-clarifier는 영역별 가중치(범위 0.25, 목표 0.25, 제약 0.20, 레거시 0.15, 우선순위 0.15)에 응답 유형 계수를 곱해 합산한다. 명확한 답변은 ×0.0, 부분적 답변은 ×0.5, "없음"·"모름"은 ×0.3, 무응답은 ×1.0이다. 총점은 0.0(완전 명확)에서 1.0(완전 모호) 사이다.

## 입력과 산출물

| 구분 | 파일 | 내용 |
|------|------|------|
| 읽는 파일 | `package.json`, `pom.xml`, `build.gradle`, `requirements.txt`, `go.mod`, `Cargo.toml` | 스택 1차 분류용 경량 스캔 |
| 읽는 파일 | 루트 `README.md` (처음 30줄), 디렉토리 이름 | 질문을 구체화하기 위한 최소 컨텍스트 |
| 쓰는 파일 | `_workspace/00_spec_report.md` | 모호성 점수, 신호, 명확화된 범위, 작업 목표, 제약, 레거시 주의사항, 우선순위, Analyzer 지시 사항(`scope_hint`·`goal_hint`·`constraint_hint`·`priority_hint`·`tier_suggestion`) |

`_workspace/`가 없으면 생성 후 재시도한다. 이 리포트는 이후 [harness-init](/skills/harness-init.md) Phase 4의 harness-evaluator가 품질 평가에 반영한다.

### tier_suggestion 가이드

| 목표 + 범위 | 권고 Tier |
|-------------|-----------|
| 코드 이해 + 특정 모듈 | Standard |
| 버그 수정 + 전체 | Standard |
| 신규 기능 개발 | Standard |
| 마이그레이션 | Full |
| 레거시 특이사항 언급 | Full |

## 예시

```text
사용자: 작업 범위 정해줘. 다음 주부터 이 시스템 마이그레이션 준비해야 해.

하네스: harness 초기화 전에 몇 가지 확인이 필요합니다 (선택 질문입니다):
        1. [범위] 분석 범위를 알려주세요. 전체 프로젝트인가요, 특정 모듈/기능인가요?
        2. [목표] 주로 API 수정인가요, 마이그레이션 준비인가요?
        3. [제약] 분석 시 주의해야 할 제약이 있나요? (DB 접속 불가, 특정 모듈 제외, 보안 민감 영역 등)
        4. [레거시] 알려진 레거시 특이사항이나 패턴이 있나요?
        모르거나 없으면 "없음" / "모름"으로 답해주세요. 전체를 건너뛰려면 "스킵"이라고 해주세요.

사용자: 1. 주문·결제 모듈만  2. Spring Boot 마이그레이션 준비  3. 운영 DB 접속 불가  4. 모름

하네스: 명세 명확화 완료 (모호성 점수: 0.15)

        목표: 마이그레이션
        범위: 주문·결제 모듈
        주요 제약: 운영 DB 접속 불가
        우선순위: 없음
        권고 Tier: Full

        다음 단계:
          harness 초기화를 진행하려면 → "하네스 초기화"
          (spec 컨텍스트가 _workspace/00_spec_report.md에 저장되어 harness-init Phase 4의
           harness-evaluator가 품질 평가에 반영합니다)
```

응답 없이 다음 단계를 요청한 경우다.

```text
사용자: 시작 전 정리해줘
하네스: (질문 4개 제시)
사용자: 스킵, 바로 하네스 만들어줘
하네스: 스킵으로 처리합니다 — GO 신호 발행.
        _workspace/00_spec_report.md: "사용자 스킵 — analyzer 자동 탐지 예정"
```

## 원칙과 주의

- **점수가 높아도 강제로 멈추지 않는다.** 사용자가 답하기 어려운 상황일 수 있고, analyzer가 코드에서 대부분 추론할 수 있다. 0.4를 넘으면 "GO (미답변 진행)"으로 넘어간다.
- **재질문은 1회 한도다.** REFINE 구간에서도 모호성 높은 영역 최대 2개에 대해 후속 질문 1개씩만 제시한다.
- **spec-clarifier는 질문 생성·점수 계산·리포트 작성만 한다.** 코드 분석이나 파일 수정은 하지 않는다. 전체 분석은 analyzer의 역할이다.
- **spec-clarifier 실패 시** "명세화 미실행 — analyzer가 자동 탐지합니다"를 안내하고 진행한다.
- **사용자가 응답 없이 다음 단계를 요청하면** "스킵"으로 처리하고 GO 신호를 발행한다.
- 스캔 결과로 스택이 확인되면 질문을 구체화한다. 예를 들어 Vue 2가 탐지되면 레거시 질문이 "Vue 3 마이그레이션을 고려하고 있나요?"로 바뀐다.
